## 1. What the tool computes

* **Type level** (default). Nodes: one source node per type in `a` (`a:<type>` -- a volley of ONE type is the unit in
  which walk gains are comparable; a pooled heterogeneous source cancels signs inside its own volley and its per-volley
  numbers depend on how many cells the spec happened to catch), the pooled target `b` (its statistic is a mean over post
  cells, well defined for any set), and every type with a cell on some path of length <= `k_max` between them (forward
  depth from a + backward depth to b over the STORED structure of `c.W`, explicit zeros included, so silent links are
  visible; an intermediate node holds all cells of its type except those in a / b). Link weight M[post, pre] = mean over
  post cells of the summed input from every pre cell (mV per post cell per pre volley; `EffectiveWeights.type_matrix`,
  cx_wedge's `total_per_post`), computed as D^-1 P^T A P. Walk gain = product of the M entries (mV^k per volley).
* **Silent links.** A link is silent when M is zero there (sign-0 presynaptic transmitter -- GLNO, the monoamines,
  unknown NT -- or a receptor-table zero) or when a silence flag covers >= 99.9 % of its raw synapses: `frozen` /
  `pruned` (optic rate units; `--frozen static` = superclass ol_intrinsic, or a FlyBrain's `rate_idx`), `never_firing`
  (max rate over a named `--recording` below `--rates-min-hz` 0.5). Every silent link is quoted with the weight it
  WOULD carry if signed: w_syn x scale[post] x min(count, cap) x the path / type / same-type gain factors
  `brain._shaped_weights` applies to that pair (obtained by running `_shaped_weights` on the graph's structure with unit
  counts and the cap off -- nothing of brain.py re-implemented). Raw counts of sign-0 entries come from
  `cache/sign0_counts.npz` (`connectome.sign0_counts`); |W| carries the signed ones.
* **k-best walks.** The `top` walks per k and per kind (`signed` = every link signed; `silent` = at least one silent
  link, ranked by the if-signed gain) are found exactly by a k-best dynamic programme over (node, has-silent-link)
  states (the product of non-negative magnitudes is monotone, so the K best walks into a node extend the K best walks
  into its predecessors). `tests/test_interp.py::PathsTests::test_kbest_walks_match_brute_force` checks it against a
  brute-force enumeration on random typed graphs (type and cell level, k <= 3, K = 4).
* **Tables.** `paths` (k, kind, rank, path, gain, gain_if_signed, signs, silent_links, raw_counts, pairs, link_mv),
  `links` (every link on a listed walk: mV per pair / per post volley signed and if-signed, raw count, share of the post
  node's raw input, sign, flags and partial-flag shares), `contributions` (Neurome fields, cell level, `value` and
  `value_if_signed`, decimal-string bodies), `b_inputs` (EVERY presynaptic type of b pooled -- `cx_shift.md` section 1 as
  a function: raw count and share, entries, mV per pair / per post volley, nt, sign, flags), and at the cell level
  `two_step_by_type` (A[b, t] @ A[t, a] summed per post cell, mV^2 per spike, signed and if-signed) and, with `--wedge`,
  `wedge_profile` (cx_wedge's 16-wedge aggregation and ring-distance profiles; `files.M16` holds the matrices).
  Summary: `strongest_silent_link_per_k` (largest |if-signed mV per post volley| **on the listed walks only**, i.e.
  scoped to the `top` walks printed per k -- not a maximum over all silent links in the graph; `validate`'s own check
  name says "on the listed walks" and the qualifier must travel with the number), the top
  signed and silent walk per k, `direct` (a -> b pooled), `dominant_silent_input_of_b` (largest raw share among the
  silent presynaptic types of b), `b_raw_input_total`, `b_silent_input_share`, `b_sign0_input_share`.
* **Level `cell`** keeps cells (nodes `type#bodyId`; endpoint cells are not intermediates); gains in mV^k per spike.

## 3. What did not reproduce, and the process notes

* Nothing failed at the numbers: 63 / 63. The first validation attempt of the previous (interrupted) session
  (`out/interp/paths/validate_console.txt` of 15:57, now overwritten) reported 37 / 44 with a PEN raw-input share of
  0.884 and every `pairs` at 0: that run used `common.raw_counts`, which installs the sign-0 count array as the WHOLE
  data vector of the count matrix (it is non-zero only on the explicit-zero entries, so every signed entry's count
  became 0). `paths.raw_counts` builds the matrix itself (|W| where W != 0, the sign-0 array where W == 0); the same
  common.py function also makes `common.links` report `synaptic_pair_count 0` for every signed entry whenever
  `counts` is not passed. **common.py bug, not mine to edit: `raw_counts` should merge, not replace** -- the health /
  decompose / trace implementers who call `common.links(...)` without `counts=` get zero counts on signed entries.
* `common.links` reads `bool(NaN)` as True for `never_firing` when no rates are given, so every entry is flagged
  `never_firing` in a structural run; `paths._contributions` rebuilds the `silent` string from the flags with NaN as
  False. Same file, same note.
* The MaleCNS type strings for PEN are `PEN_a(PEN1)` / `PEN_b(PEN2)` (the only two parenthesised types in the release),
  so the contract's worked line `--b "PEN_a|PEN_b"` selects nothing under `common.resolve`; `paths.resolve_loose`
  retries a plain token that selects nothing as `^<token>(?:\(|$)`, and the CLI line of docs/INTERP.md 7 runs as written.
* Design change against the previous draft of this tool, stated here because it changes what the walks mean: source
  nodes are per TYPE of `a` (`a:<type>`), not the pooled population. With the pooled source the top k = 2 signed walk
  was `a -> ExR4 -> b` +6,147 mV^2 (a volley of all 679 LAL / LNO / SpsP / PS196_b cells at once) and the links from
  `a` carried mixed signs (`a -> mALD1` +121 signed vs +475 if-signed, from GABA and ACh LAL types cancelling inside the
  pooled volley); per type, the same graph reads `a:LAL184 -> EPG -> b` +950 and `a:PS196_b -> GLNO -> b`, which is
  the question ("which source reaches PEN, through what"). The pooled a -> b link is kept as summary `direct`.
* No cluster job: the tool is structural. `--null` / `--replicates` / `--seed` / `--device` are accepted for CLI
  uniformity and recorded; the only rollout-dependent quantity (`never_firing`) names its `--recording`.
* **The `--recording` (`never_firing`) route is test-covered but not demonstrated on real data.** It is exercised only
  by the synthetic in-process `Recording` in `PathsTests`; no real rollout `Recording` was put through the CLI, and the
  CLI docstring's example path `out/cxroom/rec_r0` (`scripts/interp_paths.py` line 11) does not exist on disk --
  `out/cxroom/` holds `cxroom_*_s{0,1}.npz`, no `rec_r0`. Every number in this document comes from the structural arm
  (`--frozen static`), where `never_firing` plays no part.
